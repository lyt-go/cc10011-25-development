# ADR-001：重叠归因窗口下的事件归属冲突去重

- 状态：已采纳
- 日期：2026-11-16
- 相关模块：事件分析（eventanalysis）、事件归因（attribution）、分群画像（segmentprofile）、监控大盘（dashboard）

## 背景

事件分析模型的归因窗口会重叠。同一用户事件可能在「首次进入分区」与「归因窗口结束分区」
之间被两个窗口同时覆盖；在按窗口分桶统计时，该事件会被重复计入两个分组，导致样本量虚高、
置信区间失真，下游画像拿到重复口径。

事件流里存在同一唯一事件编号（`事件编号`）落在不同分区的多条记录（种子数据中的
`EVT-1002`、`EVT-1005`），必须保证同一事件在最终归因结果里只出现一次。

## 决策问题

当同一唯一事件编号在首入分区与窗口结束分区之间发生归属冲突时，应把事件锚定到哪个分区，
从而决定它进入哪个窗口/分组，且全局只进入一次。

## 备选方案

### 方案 A：首入分区锚定 + 全局去重（采纳）

以事件**首次进入的分区**为唯一锚点：按 `id` 顺序扫描事件流，同一 `事件编号` 只保留第一条
（取其 `首入分区`，缺失时回退解析 `事件时间`），后续分区出现的重复记录全部计入
`duplicates` 丢弃，不参与任何窗口归并。窗口起点再由锚定分区反推为「最早一个覆盖该事件的
窗口」。

- 优点
  - 确定性强、可解释：归属只取决于事件第一次出现的位置，不依赖窗口宽度，调整归因窗口不会
    改变历史事件的归属，结果可重放、可审计。
  - 去重发生在窗口归并**之前**，从根上保证一个事件编号只落一个分组，重叠窗口无法二次计数。
  - 与「事件首次发生即应被归因」的业务直觉一致，首触归因（first-touch）口径清晰。
  - 实现简单，只需一次排序扫描，内存与时间开销 O(n)。
- 缺点
  - 若迟到数据纠正了首入分区（首条是脏数据），需要配合事件流更正/重跑机制；当前以首条为准，
    更正通过新版本发布体现，不就地覆盖。
  - 不反映事件在结束分区的「末次触达」信息，末次触达类分析需另建模型。

### 方案 B：窗口结束分区归属（末次触达，未采纳）

以事件落入的**最后一个窗口的结束分区**为归属点，事件计入覆盖它的最晚窗口。

- 优点
  - 适合强调转化前最后一次触点的末次触达（last-touch）归因。
- 缺点
  - 归属依赖窗口宽度与扫描到的最后一条记录，窗口配置一变，同一事件的历史归属就漂移，
    不可重放、难以审计，与本平台「结果版本不可变、可追溯」的要求冲突。
  - 迟到/重复记录会把事件不断推向更晚窗口，重叠窗口下仍需额外的全局去重才能避免双计数，
    规则更复杂、边界更多（平级窗口、跨粒度窗口）。
  - 与样本准入联动时，事件在窗口间迁移会让各分组样本量不稳定，置信区间难以复现。

## 决策

采纳**方案 A：首入分区锚定 + 全局去重**。

理由：本需求的首要约束是「同一事件只进入一次归因结果」且「置信区间与样本判定可追溯」。
方案 A 在窗口归并前完成去重，归属不随窗口配置漂移，天然满足不可变版本与可重放要求；
方案 B 的末次触达语义可在未来作为独立归因模型扩展，但不应作为默认去重口径。

## 落地约束

1. 去重键为唯一事件编号 `事件编号`；重复记录只进运行台账（`丢弃重复数`、duplicates），
   绝不写入 `attributionresult`。
2. 窗口起点 = `max(事件流最早分区, 事件锚定分区 − (窗口宽度 − 1))`，保证事件被最早覆盖它的
   窗口承接，且只承接一次。
3. 每次运行在 `attributionrun` 留存输入数、去重数、丢弃重复数、各分组样本判定与置信区间口径，
   支撑审计与空态解释。
4. 结果以不可变版本发布（`attributionversion` + `attributionresult`），事件分析、分群画像、
   监控大盘统一经 `attribution_service.current_results()` 读取同一当前版本。
